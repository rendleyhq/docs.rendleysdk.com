    Settings that belong to the host, not to the project: which player/extractor implementation runs and how it is tuned depends on the host and its browser (capabilities, rollout flags), so a project must neither carry nor dictate them. They are left out of ProjectSettingsSchema, hence never written by serialize() and ignored in a loaded payload; the engine carries their live values (setters, forcedSettings) across project loads.
